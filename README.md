# DE-2027-stands

Автоматическое развёртывание стендов **демонстрационного экзамена 2027** по специальности
**09.02.06 «Сетевое и системное администрирование»** (КИМ 09.02.06-1-2027) на Proxmox VE / Альт Виртуализации.

Репозиторий площадки НСГК (Нижневартовский социально-гуманитарный колледж). Основан на скрипте
[PVE-ASDaC-BASH](https://github.com/PavelAF/PVE-ASDaC-BASH) (автор PavelAF) в редакции
[NiKeNO1540](https://github.com/NiKeNO1540/PVE-ASDaC-BASH-nvkor), лицензия GPL-3.0.

## Состав

| Файл | Назначение |
|---|---|
| `deploy.sh` | обёртка: скачивает скрипт и конфигурацию, проверяет образы, запускает развёртывание |
| `PVE-ASDaC-BASH.sh` | закреплённая копия скрипта (ветка `testing_api` форка NiKeNO1540, коммит `b369934`, 13.04.2026) |
| `configs/de27.conf` | конфигурация стендов ДЭ-2027 — три варианта (ниже) |
| `LICENSE` | GPL-3.0 (лицензия исходного скрипта) |

Скрипт **закреплён** в репозитории, а не скачивается «последней версией»: ветка `testing_api`
помечена автором как тестовая, и её изменение накануне экзамена может сломать развёртывание.

### Варианты развёртывания (`configs/de27.conf`)

| № | Назначение | ВМ и ОС | ОЗУ на стенд |
|---|---|---|---|
| 1 | Задание 1 | ISP, HQ-SRV, BR-SRV — Альт Сервер 11.1; HQ-CLI — Альт РС 11.2; HQ-RTR, BR-RTR — EcoRouter Pesto; BR-FW — Ideco NGFW v23 | ≈ 23 ГБ |
| 2 | Задание 1 (резерв) | все ВМ на Альт 11 (маршрутизаторы и BR-FW — Альт Сервер) | ≈ 11 ГБ |
| 3 | Задания 2 и 3 | как вариант 1 + два диска по 1 ГБ на HQ-SRV + `Additional.iso` на HQ-SRV, BR-SRV, HQ-CLI | ≈ 23 ГБ |

Сети стенда создаются автоматически (отдельные мосты для каждого стенда):
`ISP-HQ`, `ISP-BR`, `HQ-Net` (VLAN aware — играет роль HQ-SW), `FW-Net`, `BR-Net`.
ISP получает адрес по DHCP из внешнего моста узла (`vmbr0` или созданного утилитой скрипта).

Адаптеры ВМ на Альт подключены как `net0, net1, net2` → внутри ВМ это **ens18, ens19, ens20**
(как в шаблоне отчёта КИМ и в методических рекомендациях).

Права участника: консоль и питание своих ВМ; на HQ-SRV и HQ-CLI — изменение сетевого адаптера,
а на мост `HQ-Net` — право SDN.Use. Этого достаточно, чтобы участник сам поставил тег VLAN своего
варианта (пункт 4 задания 1). Для задания 1 и заданий 2–3 создаются **разные** учётные записи
(`Student_Z1_N` и `Student_Z23_N`), как требуют методические рекомендации ИРПО.

## 1. Образы

Скрипт берёт диски ВМ из каталога **`/root/de27/images`** на узле Proxmox:

| Файл | Для чего |
|---|---|
| `Alt-SRV_11.1.qcow2` | ISP, HQ-SRV, BR-SRV (и маршрутизаторы в варианте 2) |
| `Alt-WS_11.2.qcow2` | HQ-CLI |
| `EcoRouterOS.qcow2` | HQ-RTR, BR-RTR (варианты 1, 3) |
| `NGFW.qcow2` | BR-FW, Ideco NGFW v23 (варианты 1, 3) |
| `Additional.iso` | вариант 3 (задания 2 и 3) |

Образы **не хранятся** в Git (размер и лицензии EcoRouter/Ideco) — `.gitignore` их исключает.

### Как скопировать образы с компьютера Windows на Proxmox

В PowerShell (OpenSSH есть в Windows 10/11), подставьте адрес узла:

```powershell
ssh root@192.168.X.X "mkdir -p /root/de27/images"
scp D:\Images\*.qcow2 D:\Images\Additional.iso root@192.168.X.X:/root/de27/images/
```

Либо WinSCP: протокол SFTP, пользователь root, каталог `/root/de27/images`.

Если образы уже лежат в `/root/tmp` (как в прежних конфигах), достаточно:

```bash
mkdir -p /root/de27/images && mv /root/tmp/*.qcow2 /root/tmp/*.iso /root/de27/images/ 2>/dev/null; ls -lh /root/de27/images
```

Однократно сохраните контрольные суммы — `deploy.sh` будет сверять их перед каждым развёртыванием:

```bash
cd /root/de27/images && sha256sum *.qcow2 *.iso > images.sha256
```

> Если имена ваших файлов отличаются — переименуйте файлы (проще) или поправьте
> пути `boot_disk_0` и `iso_1` в `configs/de27.conf`. Другой каталог: `DE27_IMG=/путь bash deploy.sh`.

## 2. Развёртывание

Proxmox → узел → **Shell** (под root), вставить строку:

```bash
(r=docent-nv/DE-2027-stands b=main; curl -sfOL "https://raw.githubusercontent.com/$r/$b/deploy.sh" && bash deploy.sh; rm -f deploy.sh)
```

Дальше — меню скрипта PVE-ASDaC-BASH:

1. **1 — Развертывание стендов**.
2. Выбрать вариант: 1 (задание 1), 2 (задание 1 на Альт) или 3 (задания 2 и 3).
3. Указать номера стендов, например `1-10` (по числу рабочих мест).
4. Проверить внешний мост (обычно `vmbr0`), хранилище (`local-lvm` / `local-zfs`) и запустить.
5. В конце скрипт выведет логины и пароли участников — сохраните их для карточек участников
   (можно выбрать формат для вставки в Excel).

«Тихий» режим без вопросов (пример: 10 стендов варианта 1):

```bash
(r=docent-nv/DE-2027-stands b=main; curl -sfOL "https://raw.githubusercontent.com/$r/$b/deploy.sh" && bash deploy.sh -var 1 -n 1-10 -si; rm -f deploy.sh)
```

Посмотреть итоговую конфигурацию без развёртывания: `bash deploy.sh -sh /root/de27/config-preview.txt`.

### Если во внешней сети нет DHCP

ISP должен получать адрес по DHCP. Если в сети колледжа DHCP для виртуальных машин нет, в меню скрипта
выберите **3 — Утилиты → Создание WAN (VM Network) bridge** (PVE 8.1+, нужен пакет `dnsmasq`):
скрипт создаст SDN-сеть с NAT и DHCP — укажите её как внешний мост при развёртывании.

## 3. Во время экзамена

- **Сброс стенда**: у каждой ВМ создан снимок `Start` — откат: ВМ → Снимки → `Start` → Откат,
  либо меню скрипта **2 — Управление стендами**.
- **Отключение / включение учётных записей и смена паролей** — меню **2 — Управление стендами**.
- **Удаление стендов** после экзамена — меню **2 — Управление стендами** → удаление.
- Задания 2–3: после развёртывания варианта 3 технический эксперт выполняет преднастройку
  (адресация, NAT, GRE, OSPF, DHCP, DNS, Samba DC на BR-SRV, sshuser/net_admin, SSH-порт)
  и ставит теги VLAN на HQ-SRV/HQ-CLI по варианту задания.

## 4. Первая проверка на площадке (один раз)

1. Развернуть **один** стенд варианта 1 (`-n 1`), запустить все ВМ.
2. На HQ-SRV: `ip -br link` — интерфейс должен называться `ens18`.
3. На HQ-RTR: `show port brief` — определить, какой порт смотрит в ISP-HQ, а какой в HQ-Net
   (сравнить MAC с Proxmox → ВМ → Оборудование). Результат внести в методички (шаг 0).
4. Под учётной записью участника изменить тег VLAN на HQ-SRV — должно получиться.
5. Удалить тестовый стенд через меню **2**.

## 5. Как обновлять

- Изменили конфигурацию — коммит в `configs/de27.conf`, новая версия подхватится при следующем запуске.
- Обновить сам скрипт: заменить `PVE-ASDaC-BASH.sh` новой версией из форка и **проверить на одном стенде**
  до экзамена.
- Развернуть из локальной копии репозитория (без Интернета до GitHub):
  `git clone https://github.com/docent-nv/DE-2027-stands && cd DE-2027-stands && DE27_LOCAL=1 bash deploy.sh`.
